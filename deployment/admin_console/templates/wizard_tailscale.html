Step 1: Deploy Headscale on WSL2

Run the Headscale playbook from your WSL2 terminal to install and start the control server:

cd /mnt/c/Users/keyser/source/repos/keyser-sila-testing/deployment
export ANSIBLE_CONFIG=$(pwd)/ansible.cfg
ansible-playbook playbooks/headscale.yml --ask-become-pass

This will:

  • Install Headscale v0.25.1 from the .deb package
  • Create the config at /etc/headscale/config.yaml
  • Start the Headscale service
  • Create a sila user namespace
  • Generate a reusable pre-auth key
Note the pre-auth key and server URL from the playbook output — you'll need both in the next steps.
Step 1: Create a Tailscale Account

If you don't already have one, sign up for a free Tailscale account.

  • Go to https://login.tailscale.com
  • Sign in with Google, Microsoft, or GitHub
  • The free plan supports up to 100 devices
Step 2: Note the Pre-Auth Key

The Headscale playbook output displayed a pre-auth key. Copy it now.

To generate a new key later, run:

sudo headscale preauthkeys create --user sila --reusable --expiration 720h
Step 2: Generate a Pre-Auth Key

Create a reusable auth key so Ansible can register machines without manual login.

  1. Go to Settings → Keys in the Tailscale admin console
  2. Click Generate auth key
  3. Check Reusable and Pre-approved
  4. Set an expiry (90 days recommended)
  5. Copy the key (starts with tskey-auth-)
Keep this key secret! It allows any machine to join your network.
Step 3: Store the Key in Ansible Vault

Run this command from your WSL2 terminal (with the Ansible venv activated):

cd deployment
ansible-vault create inventory/group_vars/all/vault.yml

Add this line to the vault file:

vault_tailscale_auth_key: "YOUR-PRE-AUTH-KEY-HERE"

If inventory/group_vars/all/vault.yml already exists, use ansible-vault edit instead of create.

Step 4: Set the Headscale Server URL

Edit inventory/group_vars/all.yml and uncomment/set the Headscale URL from the playbook output:

headscale_server_url: "http://<WSL2_IP>:8080"

This tells the Tailscale clients to register with your Headscale instance instead of Tailscale SaaS.

WSL2 IP caveat: The WSL2 IP can change on reboot. For a stable setup, use netsh interface portproxy on Windows to forward a fixed port, or set a static IP in .wslconfig.
Step 4: Confirm Control Plane Setting

Make sure headscale_server_url is commented out (or not set) in inventory/group_vars/all.yml. This ensures clients register with Tailscale SaaS.

# headscale_server_url: "http://..."  ← must be commented out
